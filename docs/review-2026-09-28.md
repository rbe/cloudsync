# Review 2026-09-28 — findings and fix plan

A review of cloudsync at commit `3f11a75` (requirements, architecture, code), written as a hand-off for the session that fixes it. Every finding marked **verified** was reproduced by running the script. Line numbers refer to `3f11a75` and will drift as fixes land.

**Updated 2026-09-29** with the owner's answers; see [Owner decisions](#owner-decisions-2026-09-29). They changed F2, F4–F6, F8, F11, F13, F16, F19, D3 and D6, and added F23 and F24.

**Verdict.** The design is sound: rclone moves the data and the script adds policy (aliases, gates, locks, schedule, notifications). It is not yet safe to trust with "all my data". Several bugs silently stop backups or weaken the delete guards. The most urgent is that `run --force`, the documented way past the delete limit, does not work (F1).

## How the review was tested

- Ran the script on Linux (bash 5.2) against real rclone v1.60.1 (Ubuntu package) and v1.75.1 (built from source).
- Each test used a throwaway `$HOME` with a fake iCloud tree. The rclone remotes `Nx:`/`Filen:` were local folders; for bisync, `Nx:` was served by a local `rclone serve webdav`.
- An rclone wrapper logged every argv; `osascript`, `brctl`, `launchctl` and `xattr` were stubbed.
- **Not tested:** macOS-only behaviour (Full Disk Access/TCC, `brctl`, launchd) and macOS `/bin/bash` 3.2. See F8, F11, F17 and F20.
- **2026-09-29 update:** checks F2, F4–F6, F8 and F13 were revised to match the owner's decisions, and F23–F24 were added. On rclone v1.75.1 the current code gives 3 passed, 20 failed. Two scratch copies with sketch fixes were run against the new checks:
  - With bisync removed, F2, F4–F6, F8, F13, F23 and F24 pass.
  - With bisync kept and backups on the remote side only, F5 passes.
  - G1–G3 stayed green in every run.

## Findings

### F1 — `run --force` does not lift the delete limit (High, verified)

- **Symptom:** a destination has 60 files to delete, and `MAX_DELETE=50` is the default. `cloudsync run <job> --force` moves 50 files into the backup dir, then rclone stops with `--max-delete threshold reached` (rc=7). The run is recorded as failed. N deletions need about N/50 forced runs. Same on rclone 1.60 and 1.75.1.
- **Where:** `cloudsync:605-607`. `FORCE` only skips the pre-flight (`cloudsync:578`); the real `rclone sync` always gets `--max-delete "$MAX_DELETE"`. The README's Safety section and `usage` promise that `--force` skips max-delete.
- **Fix (sketch verified):**
  ```bash
  local maxdel="$MAX_DELETE"; [ "$FORCE" = 1 ] && maxdel=-1
  ...  --max-delete "$maxdel" ...
  ```
  Keep `--max-delete` on normal runs: it is the backstop when the source changes between pre-flight and run.
- **Acceptance:** F1 and G2.

### F2 — One malformed row silently stops every scheduled job (High, verified)

- **Symptom:** a non-interactive `run all` with one invalid row (e.g. spaces instead of tabs) exits 1. The error goes only to `launchd.err.log`: 0 notifications, 0 status records. `status` keeps showing the previous results. By contrast, a pre-flight abort does notify.
- **Where:** `run_set` (`cloudsync:649`) and `run_job` (`cloudsync:512`) return before `notify`/`record_status`. The same applies to `need_rclone` and `load_job` failures.
- **Fix:**
  - On validation failure, call `notify "cloudsync: job map invalid" "<first error>"`.
  - Record a map-level status (e.g. `$STATE_DIR/status/.jobmap`, outcome `invalid`) that `cmd_status` shows as a banner.
  - Do the same for "rclone not found".
  - **Decided (owner, 2026-09-29): fail-closed.** An invalid map keeps blocking every job; the fix only makes the block visible. The same applies to every new validation (F3, F7, F9, F13, F14): one bad row blocks all jobs, with a notification.
  - A blocked map stops all backups until someone fixes it, which makes D4 (staleness alert) more important.
- **Acceptance:** F2. The check also fails if a valid row runs while the map is invalid.

### F3 — Duplicate job names (High, verified)

- **Symptom:** two rows named `dup` (targets `Nx:first` and `Nx:second`) pass validation. `run all` runs the *first* row twice; `Nx:second` is never created. `status` shows both rows green.
- **Where:** `load_job` takes the first match (`cloudsync:374-386`); `validate_jobs_file` (`cloudsync:404-436`) does not check for duplicates.
- **Fix (sketch verified):** track seen names in the validator and reject repeats. Do it inside the single parser from F14.
- **Acceptance:** F3.

### F4 — `MAX_DELETE` means files for sync but percent for bisync (High for bisync, verified on 1.75.1)

- **Status:** only if bisync stays. The review recommends removing it (Q1).
- **Symptom:** bisync job, 200 files on both sides, 60 deleted on the source (30%):

  | `MAX_DELETE` | What happened |
  |---|---|
  | 50 (default) | All 60 deletions propagated; the same deletions in `sync` mode are blocked. |
  | 10 | "Safety abort: too many deletes (>10%, 60 of 200)". |
  | 500 | The guard is effectively off. |

  rclone does *not* also cap the underlying delete count.
- **Where:** `cloudsync:610-613` passes `--max-delete "$MAX_DELETE"` to bisync. `examples/config` and the README describe `MAX_DELETE` as "this many files".
- **Fix:**
  - Add a separate `BISYNC_MAX_DELETE_PCT=50`, validated as an integer 0–100 at startup, and pass it to bisync.
  - When `FORCE=1`, also pass bisync's own `--force` (bypasses its percentage check).
  - Document both knobs.
- **Acceptance:** F4. Also consider a check that `MAX_DELETE=10` does not make bisync abort a 15% deletion.

### F5 — Bisync deletions leave no copy (High for bisync, verified)

- **Status:** only if bisync stays. The review recommends removing it (Q1).
- **Symptom:** after a baseline, deleting 10 files on the source and running bisync deletes them on `Nx:` with no copy in any `.cloudsync-backups`. `sync` mode keeps such copies.
- **Where:** `cloudsync:609-614`: no `--backup-dir1` / `--backup-dir2`. rclone 1.75.1 lists both flags: "Must be a non-overlapping path on the same remote".
- **Fix:**
  - Pass `--backup-dir2 <base(path2)>/<job>/<ts>` (sketch verified).
  - Pass `--backup-dir1` only when path1 is a remote. Under Q3, backups never go to a local disk, so deletions that bisync makes on a local path1 (usually iCloud) get no copy. That is one reason to remove bisync.
  - Reuse `backup_base_for_dest`, and give bisync the same `--exclude "/$BACKUP_ROOT_NAME/**"` so root paths don't see their own backups.
  - Make `list backups` / `clean backups` enumerate remote path1 bases too; `backups_bases` only walks destinations today.
  - Check whether adding the exclude to an existing bisync job requires a `--resync`.
- **Acceptance:** F5. The copy must be on the remote, not on the Mac.

### F6 — First bisync baseline into an empty folder is impossible (Med for bisync, verified)

- **Status:** only if bisync stays. The review recommends removing it (Q1).
- **Symptom:** source has 5 files, destination folder is new and empty.
  - `cloudsync resync <job>` aborts on the empty-side guard ("lists 0 files").
  - `resync <job> --force` is ignored: `main` passes only `$1`, and `resync --force <job>` → "Unknown job: --force".
  - `run <job> --force` refuses with "no bisync baseline".

  The only workaround is putting a dummy file in the empty side.
- **Where:** `cloudsync:582-583` (guard checks both sides on resync), `cloudsync:1239` (`resync` has no flag parsing), `cloudsync:546-558`.
- **Fix:**
  - Minimum (sketch verified): let `resync` parse `--force` like `run`.
  - Better: on `--resync`, skip the empty-*destination* check, because resync never deletes (it unions both sides; path1 wins files that differ). Keep the source check unless `--force`.
  - Update the fzf menu's "Resync" action accordingly.
- **Acceptance:** F6.

### F7 — Overlapping destinations are not detected (Med, verified)

- **Symptom:** three jobs: `icloud-to-nx` (→ `Nx:backup`), `nx-to-filen` (`Nx:` → `Filen:`, root mirror) and `icloud-to-filen` (→ `Filen:direct`).
  - Every `run all`, `nx-to-filen` moves `Filen:direct` into Filen's backup dir, then `icloud-to-filen` re-uploads it.
  - Validation says "job map OK", every job shows OK, and Filen's backups grow by a full copy per run.
  - With more than 50 files, `nx-to-filen` aborts on every run instead, so the mirror goes stale.

  Two paths into one destination (a "diamond") is the general shape. A sync or bisync writing into a tree that another job owns has the same problem.
- **Where:** the validator (`cloudsync:404-436`) looks at rows one at a time.
- **Fix:**
  - Normalise each side to `(remote, path)`; iCloud aliases and `~/` resolve to local absolute paths. Paths overlap when equal or one is a prefix of the other plus `/`; a remote root such as `Filen:` overlaps everything on that remote.
  - **Error:** two jobs' destinations overlap.
  - **Error:** a bisync path overlaps another job's destination.
  - **Error:** a cycle (A's destination overlaps B's source and B's destination overlaps A's source).
  - **Allow chains:** A's destination overlapping B's source, e.g. iCloud → Nx → Filen.
  - Limitation: two remote names pointing at the same storage (an alias) can't be detected statically; document it.
- **Acceptance:** F7. It also requires the plain chain to keep validating.

### F8 — `~/…` paths resolve to `$HOME/~/…` (High, verified on bash 5.2; bash 3.2 unverified)

- **Severity raised from Med:** the owner wants the whole home directory backed up (Q5), so `~` sources become the main use.
- **Symptom:**
  - A destination of `~/Backups/iCloud` wrote into `$HOME/~/Backups/iCloud`, a folder literally named `~`.
  - A `~/…` *source* resolves to a non-existent path: `copy` fails with "directory not found", and `sync` aborts with a misleading "no Full Disk Access" message.
  - A bare `~` (a whole-home source) is not resolved at all: rclone receives the literal `~` as a relative path and fails.
- **Where:** `cloudsync:301`: `"${1#~/}"`. Bash tilde-expands the pattern, so it never matches the literal `~/`. Line 369 already uses the correct `\~/`. No case handles a bare `~`.
- **Fix (sketch verified):**
  ```bash
  "~")    printf '%s' "$HOME" ;;
  "~/"*)  printf '%s/%s' "$HOME" "${1#\~/}" ;;
  ```
- **Check on a Mac:** `/bin/bash -c 'x="~/a"; echo "${x#~/}"'` must print `a`. If it prints `~/a`, macOS is affected too.
- **Operator note:** if a folder named `~` exists in a home directory, delete it with `rm -r "$HOME/~"`, never `rm -rf ~`.
- **Acceptance:** F8. The check now uses `~` *sources*, because F13 rejects local destinations.

### F9 — Quotes in the extra-flags column are passed literally (Med, verified)

- **Symptom:** `--exclude '*.tmp'` reaches rclone as `'*.tmp'` including the quotes, so nothing is excluded (`scratch.tmp` was copied). Patterns containing spaces cannot be expressed at all.
- **Where:** `cloudsync:367` (`read -r -a`, whitespace split, no quote handling). `examples/jobs.tsv:10` teaches the quoted form: `--exclude '*.tmp'`.
- **Fix:**
  - Recommended: the validator rejects `'` and `"` in the extra column, with a hint to use `--filter-from <file>` for patterns with spaces.
  - Fix the example to `--exclude *.tmp`.
  - Don't `eval` the column: it would execute command substitutions.
- **Acceptance:** F9. It passes if the map is rejected or the pattern is honoured.

### F10 — `verify --deep` claims hashes it didn't compare (Med, verified)

- **Symptom:** the check uses a `crypt` destination (no hash support). rclone logged `No common hash found - not using a hash for checks`, compared sizes only, and a same-size content change passed. cloudsync printed "verify OK … (matching hashes)".
- **Where:** `cloudsync:969-985`.
- **Fix:**
  - After `rclone check`, grep the verify log for `No common hash found`; also look for per-file "could not be checked" notices and confirm the exact wording for the rclone version. If found, say "sizes only — no common hash" and don't report success as a hash check.
  - Add `verify --bytes` using `rclone check --download` for a real content comparison, which downloads both sides.
  - For crypt destinations, mention `rclone cryptcheck`.
- **Acceptance:** F10.

### F11 — `@prefetch` downloads the whole `Mobile Documents` tree (Med, verified call; effect unverified)

- **Symptom:** for an `iCloudAll` job with `--filter-from icloud.filter`, prefetch runs `brctl download "$HOME/Library/Mobile Documents"` on every run, ignoring the filter.
  - If `brctl download` recurses as the script assumes, this pulls all of iCloud (including excluded app data) onto the Mac each run.
  - That defeats "Optimize Mac Storage" and can fill the disk when iCloud is larger than free space.
- **Where:** `cloudsync:331-340` (call at `:574`).
- **Unverified (test on macOS first):** whether `brctl download` recurses into directories, whether it waits for completion, and whether rclone can read dataless files on demand in the launchd context.
- **Fix options:**
  - Prefetch only the files the dry-run will transfer.
  - Restrict `@prefetch` to explicit subfolders.
  - Drop it if on-demand reads work.
- **Owner principle (Q3):** this tool must not use local disk space. Materializing iCloud files on the Mac goes against that, so prefer on-demand reads. If a prefetch is needed, limit it to what the dry run will transfer, and evict those files again after the upload (`brctl evict`, unverified).
- **Acceptance:** F11 (no `brctl` call on the `Mobile Documents` root).

### F12 — Auto-clean removes a running job's lock after 12 h (Med, verified)

- **Symptom:** a job's lock is 13 h old and its owner process is alive. An unrelated `cloudsync dry other` (auto-clean runs after every run and dry run) removed the lock, and the next `run <job>` started a second concurrent copy. This matters for multi-day first uploads.
- **Where:** `prune_state`, `cloudsync:1027-1031`: removes by age only, unlike `run_job`, which checks the PID (`cloudsync:517-521`).
- **Fix (sketch verified):** skip lock dirs whose `pid` passes `kill -0`.
- **Acceptance:** F12.

### F13 — Local destinations keep their backups on the internal disk (Med, verified)

- **Symptom:** `sync` to `/Volumes/SSD/backup` moved deleted files into `~/.cloudsync-backups/<job>/<ts>` on the internal disk (3 files), with none on the SSD. Backups leave the backup drive and fill the Mac.
- **Where:** `backup_base_for_dest`, `cloudsync:319-323`: `$HOME/.cloudsync-backups` for every local destination.
- **Decided (owner, 2026-09-29):** no backup space on local disks, because this is a cloud sync/backup tool. One backup layout everywhere (F16).
- **Consequence:** rclone keeps a backup only on the destination's own storage (`--backup-dir` must be on the same remote). A job that writes into a local path can't have backups without using local disk.
- **Fix:**
  - Remove the `$HOME/.cloudsync-backups` fallback.
  - The validator rejects `sync` (and `bisync`, if kept) into a local destination: `~/…`, `/abs`, `/Volumes/…` or an iCloud alias. The message says why. Rejection is fail-closed, as in F2. Sketch verified.
  - Recommended, *owner to confirm*: reject every local destination, `copy` included, once `copy` keeps backups (F23). Sources may then be local or remote; destinations are always rclone remotes.
  - Update the README (the Paths list; "Skip this if every job is local" under After setup) and `examples/jobs.tsv`.
  - Old backups: `list backups` / `clean backups` also show and prune an existing `~/.cloudsync-backups`, and `doctor` warns while it exists, so the space can be reclaimed.
- **Acceptance:** F13: a `sync` into a local path is rejected.

### F14 — Parser, schedule, EDITOR and doctor edge cases (Low, all verified)

- **F14a — indented `# comment`:** passes validation (`_jobs_skip_line` allows leading whitespace) but the six other readers treat it as a job. `dry all` then prints `Unknown job: #`, `note`, … and exits 1.
- **F14b — job name with a space:** passes validation, but `for n in $(job_names)` (`cloudsync:651`, `:998`) word-splits it, so the job never runs via `all`.
- **Fix for F14a/b (and F3):**
  - Write one parser used by all seven readers: `job_names`, `load_job`, `validate_jobs_file`, `list_jobs`, `cmd_menu`, `_doctor_jobs`, `backups_bases`.
  - It applies one skip rule (blank or `^[[:space:]]*#`) and strips `\r`.
  - It restricts names to `^[A-Za-z0-9._-]+$`, because names become file names for logs, locks, status and backup folders.
  - Iterate jobs with `while read`, not `for n in $(…)`.
- **F14c — `schedule install daily 3`:** schedules 03:03, because `m="${time##*:}"` without a colon takes the whole string (`cloudsync:733-737`). Validate `^([01]?[0-9]|2[0-3]):[0-5][0-9]$` and a positive integer interval; reject anything else.
- **F14d — `EDITOR` with arguments:** `EDITOR="code --wait"` fails with "command not found" (`cloudsync:445`). Sketch verified: `${VISUAL:-${EDITOR:-vi}} "$JOBS_FILE"` (unquoted, intentionally word-split).
- **F14e — doctor FDA check:** doctor reports "NOT readable … lacks Full Disk Access" when iCloud Drive has a folder whose name contains "error" (e.g. `Error Reports/`). It greps the listing for `error` (`cloudsync:921`). Use rclone's exit status instead (`if out="$(rclone lsf … 2>&1)"; then …`), and also check `$ICLOUD_MOBILE` when a job uses `iCloudAll`.
- **Acceptance:** F14a–F14e.

### F16 — Backup location is documented wrong (Low, verified)

- README (`Files` table, line 118) and `usage` (`cloudsync:1207`) say `<dest>/.cloudsync-backups/<job>/<timestamp>`.
- The code uses the **remote root**: dest `Nx:Photos` → `--backup-dir Nx:.cloudsync-backups/photos/<ts>`. Local destinations use `~/.cloudsync-backups` (F13).
- **Decided (owner, 2026-09-29): one layout everywhere.**
  - Keep the code's remote-root layout, `<remote>:.cloudsync-backups/<job>/<timestamp>/`, for every mode that keeps backups: `sync`, `copy` (F23), and `bisync` if it stays.
  - Fix the docs to match: README line 118, `usage` (`cloudsync:1207`) and the `BACKUP_ROOT_NAME` comment in `examples/config` ("on each destination").
- **Why the remote root rather than `<dest>/…`:**
  - There is one known place per remote.
  - The root-anchored `--exclude /.cloudsync-backups/**` keeps backups out of root-to-root mirrors, so a chain like `Nx:` → `Filen:` doesn't copy Nx's backups.
  - `list backups` / `clean backups` need only one base per remote.

### F17 — `doctor` checks the wrong context (Med)

- Terminal usually has Full Disk Access; the launchd agent may not. `doctor` run from Terminal gives false comfort, as its own message admits (`cloudsync:923`).
- **Fix:** `doctor --launchd`. Install a temporary LaunchAgent that runs `cloudsync doctor` with output to a file, kickstart it, wait, print the result, then remove the agent.

### F18 — Each sync run lists the source three times (Low, verified)

- One `sync` run makes three rclone calls: `rclone size` (source), `rclone sync --dry-run` (both sides) and `rclone sync` (both sides). For root-to-root WebDAV mirrors that dominates runtime.
- **Fix:** derive "source is empty" from the dry run instead of `rclone size`, keeping the gate's semantics (G1).

### F19 — Bisync baselines live in `~/Library/Caches` (Low)

- **Status:** only if bisync stays. The review recommends removing it (Q1).
- rclone's default workdir on macOS is `~/Library/Caches/rclone/bisync`, which cleanup tools tend to treat as disposable (not verified for any specific tool).
- A lost baseline forces `--resync`, which unions both sides and brings back files deleted since the last run.
- **Fix:** pass `--workdir "$STATE_DIR/bisync"` and update `_bisync_workdir` (`cloudsync:795-800`). Migrate existing listings or require one resync.
- Note: `_bisync_canon` does not match rclone's naming for `alias` remotes (rclone uses the resolved local path), so the baseline check would always fail for them.

### F20 — Full Disk Access may not survive `setup --upgrade` (Med, unverified)

- Wave 1 assumes a stable path keeps the FDA grant. I believe macOS stores a code requirement with the grant. For an ad-hoc-signed binary (typical for Go builds) that requirement is the build's `cdhash`, so a replaced binary at the same path loses FDA.
- Failure is safe (runs abort and notify), but backups stop.
- **Check on a Mac:** `codesign -d -r- ~/.local/bin/rclone`. `designated => cdhash H"…"` means the grant is build-specific.
- **Fix:** after `setup --upgrade`, print a reminder to re-grant and re-verify from launchd (F17). Correct `docs/waves.md` if confirmed.

`_install_rclone` (`cloudsync:142-188`) installs whatever `rclone-current-osx-<arch>.zip` returns over HTTPS; `docs/waves.md` defers checksums. Check what the rclone project publishes per release and verify against it.

### F23 — `copy` keeps no copy of the files it overwrites (Med, verified)

- **Symptom:** a `copy` job ran, the 5 source files were then changed, and the next run overwrote all 5 on `Nx:`. No original was kept anywhere; `sync` keeps them (G3).
- **Why it matters:** the example job map calls `copy` the safest mode. Yet if the source gets corrupted or encrypted (a broken app, ransomware), `copy` replaces the good copies with no way back.
- **Where:** `cloudsync:597-598`: `rclone copy` without `--backup-dir`.
- **Fix (sketch verified):**

- **Acceptance:** F23.

### F24 — Backup retention: 30 days by default, configurable (Med, owner decision)

- **Decided (owner, 2026-09-29):** deleted or overwritten files stay recoverable for 30 days by default, and the period is configurable.
- **Today:**
  - `BACKUP_RETENTION_DAYS=90` (`cloudsync:58`, `examples/config`) is only the default of the manual `clean backups`. Nothing prunes automatically (README Safety; `docs/waves.md` lists auto-pruning as out of scope).
  - `backup_ts_epoch` (`cloudsync:1099`) uses BSD `date -j`. On Linux (tests, CI per F22) no backup date parses, so nothing is ever pruned.
- **Fix:**
  - Default `BACKUP_RETENTION_DAYS=30`. Validate it as a positive integer at startup, and refuse to run otherwise (fail-closed, Q2). Update `examples/config` and the README.
  - Make `backup_ts_epoch` portable (sketch verified). Substring expansion such as `${1:0:8}` exists in bash 3.2.
    ```bash
    backup_ts_epoch() { date -j -f '%Y%m%d-%H%M%S' "$1" +%s 2>/dev/null ||
                        date -d "${1:0:8} ${1:9:2}:${1:11:2}:${1:13:2}" +%s 2>/dev/null; }
    ```
  - Keep taking the age from the backup folder's name, which is the time of the deletion or overwrite. See [Verified OK](#verified-ok-dont-fix) for why file dates don't work.
  - Recommended, *owner to confirm*: prune automatically, so that "30 days" holds without a manual step. After `run all`, prune at most once a day (a stamp file in `$STATE_DIR`), switchable with `AUTO_CLEAN_BACKUPS=1|0`. This reverses the "not in scope" line in `docs/waves.md`; update it and the comment above `backups_bases` (`cloudsync:1062-1066`).
- **Consequence:** with 30 days, silent damage (a mass overwrite, ransomware) must be noticed within 30 days. That raises the priority of D3 and D4. Server-side versions (D2) are independent of this retention.
- **Acceptance:** F24: `clean backups` without `--days` purges a 31-day-old backup and keeps a 29-day-old one.

## Design backlog (requirements level)

Today cloudsync is a mirror with a recycle bin, not yet a backup.

- **D1 — Restore, and honest terminology.**
  - `.cloudsync-backups/<job>/<ts>/` holds only what that run replaced or deleted, yet the README and code call them "snapshots".
  - Getting back "the state of 1 June" is manual reassembly.
  - Add `cloudsync restore <job> <path> [--from <ts>]` (restore to a separate location by default, never in place) and a way to find a file across backup folders.
  - Document a restore drill.
- **D2 — One copy the Mac can't delete.** The Mac's `rclone.conf` can delete every destination and its backups: ransomware, a bad job row or a stolen Mac can wipe all copies. Options, with *Owner decision*:
  - Server-side versions and trash on Nextcloud and Filen (outside cloudsync; document it).
  - An append-only backup tool (restic, kopia) for the core data.
  - Encrypting `rclone.conf` with `--password-command` backed by the Keychain.
- **D3 — Mass-change gate.** Rewriting every file in place passes the pre-flight ("0 deletion(s)"). Only the backup dir saves the originals (G3; `copy` keeps none until F23), and after F24 they are purged after 30 days. Also count updated files in the same dry run, with absolute and percentage limits, and abort and notify above them. Confirm rclone's exact dry-run log strings for updates.
- **D4 — Staleness alert.**
  - Failures notify, but not running at all doesn't: a manual schedule, F2, an unloaded agent, a sleeping Mac.
  - Record `last_ok` per job, show "last success" in `status`, and notify when it is older than `STALE_HOURS`.
  - Only a check that runs independently of the sync job can notice when nothing runs.
- **D5 — Job graph.** Beyond F7: chains depend on file order today. Consider explicit ordering and a global lock for `run all`.
- **D6 — Coverage: the home directory (decided), and encryption.**
  - *Decided (owner, 2026-09-29):* "all my data" means the home directory, not only iCloud Drive. Today only iCloud Drive (plus app `Documents` folders) is covered; the Photos library, Notes, Contacts, Calendars and Mail are not files there.
  - Prerequisites: F8 (`~` sources). Home-wide jobs raise the stakes of F12 (multi-day first upload), F17 (launchd access) and F18 (listing cost).
  - **Exclusions:** ship an `examples/home.filter` for the owner to review. At least:
    - `Library/Caches/**`, `Library/Logs/**`, `.Trash/**`
    - `Library/Mobile Documents/**`: already covered by the iCloud job, and reading dataless files would download them.
    - `Library/CloudStorage/**`: other clouds' File Provider folders; reading them would download those clouds.
    - a legacy `.cloudsync-backups/**`
  - **Delete gate:** `~/Library` churns daily. A single `~` job will likely exceed `MAX_DELETE` on ordinary days, abort (fail-closed), and train the habit of `--force` (expected, not measured). Prefer several jobs, each with its own filter: Documents, Desktop, Pictures, projects, dotfiles, selected `Library` folders.
  - **Open databases:** Mail, Messages, Photos and browsers keep databases open. They are copied file by file, not as a snapshot, so a copy can be inconsistent. Exclude them and rely on the apps' own sync, or copy from an APFS snapshot (untested).
  - **Photos:** with "Optimize Mac Storage", the originals live in iCloud Photos, not on disk, so a home backup doesn't contain them. Downloading them would conflict with Q3. *Owner decision.*
  - **Secrets:** the home directory holds `~/.ssh`, `~/Library/Keychains` and `~/.config/rclone/rclone.conf`, which has the credentials for every remote. On a server without end-to-end encryption, whoever can read the account can read them. Nextcloud stores files unencrypted unless the server encrypts. Encrypt the home job (an rclone `crypt` remote, or a destination with client-side encryption), or exclude the secrets. *Owner decision.*
  - **Tool fit:** for a whole home directory, a snapshot backup tool (restic or kopia; both can store to rclone remotes) gives point-in-time restore (D1), retention rules, encryption and, set up append-only, D2. cloudsync could schedule it. *Owner decision*; the fixes above don't depend on it.

## Test-harness pitfalls

- bisync names its state files `<path1>..<path2>.*` from both full canonical paths. Deep temp directories hit "file name too long".
- An `alias` remote resolves to its local path in those names, so the checks serve `Nx:` over WebDAV.
- `rclone serve webdav` caches directory listings; the checks use `--dir-cache-time 0s`.
- `pkill -f 'rclone serve …'` also matches the shell that runs it; use `pgrep -f '[r]clone serve'`.
- `a && b && c & pid=$!` backgrounds the whole chain, including any environment setup.
- F8's `~/…` result depends on the shell behind `#!/bin/bash`: 5.x on Linux fails; macOS 3.2 is unverified. The bare `~` part fails on any bash.

# cloudsync regression checks for docs/review-2026-09-28.md

WORK="${CLOUDSYNC_TEST_DIR:-$(mktemp -d "${TMPDIR:-/tmp}/cs.XXXXXX")}"

[ -x "$CLOUDSYNC" ] || { echo "cloudsync not found at $CLOUDSYNC (run from the repo root)"; exit 2; }
[ -n "$REAL_RCLONE" ] || { echo "rclone not found (set REAL_RCLONE)"; exit 2; }

PASSES=0; FAILS=0; SKIPS=0; WEBDAV_PID=""; BG_PIDS=""
pass() { PASSES=$((PASSES+1)); printf 'PASS %-4s %s\n' "$1" "$2"; }
fail() { FAILS=$((FAILS+1));   printf 'FAIL %-4s %s\n' "$1" "$2"; }
skip() { SKIPS=$((SKIPS+1));   printf 'SKIP %-4s %s\n' "$1" "$2"; }
cleanup() {

newenv() {   # $1 = check id -> sets T, HOME, CALLS, RCLONE_ARGV_LOG, ICLOUD

#!/bin/bash
{ printf '%q ' rclone "$@"; echo; } >> "$RCLONE_ARGV_LOG"
exec "$REAL_RCLONE" "$@"
EOF

    printf '#!/bin/bash\necho "%s $*" >> "$CALLS"\nexit 0\n' "$s" > "$T/stubs/$s"

  export RCLONE_CONFIG="$HOME/.config/rclone/rclone.conf"

# Nx: over WebDAV instead of an alias: keeps bisync session file names short
# (an alias resolves to the full local path) and is closer to Nextcloud.
webdav_nx() {
  local port=$((20000 + RANDOM % 20000)) i
  "$REAL_RCLONE" serve webdav "$T/remotes/nx" --dir-cache-time 0s \
    --addr "127.0.0.1:$port" >"$T/webdav.log" 2>&1 &
  WEBDAV_PID=$!
  printf '[Nx]\ntype = webdav\nurl = http://127.0.0.1:%s\nvendor = owncloud\n\n[Filen]\ntype = alias\nremote = %s\n' \
    "$port" "$T/remotes/filen" > "$RCLONE_CONFIG"
  for i in $(seq 1 50); do "$REAL_RCLONE" lsf Nx: >/dev/null 2>&1 && return 0; sleep 0.1; done
  return 1
}
stop_webdav() { [ -n "$WEBDAV_PID" ] && kill "$WEBDAV_PID" 2>/dev/null; wait "$WEBDAV_PID" 2>/dev/null; WEBDAV_PID=""; }
need_bisync() { [ "${RCLONE_MINOR:-0}" -ge 66 ] || { skip "$1" "needs rclone >= 1.66 for bisync flags"; return 1; }; }

jobs() {     # jobs "name|mode|src|dst|extra" ...  -> TAB-separated jobs.tsv

}
mkfiles() {  # $1 = dir, $2 = count, $3 = prefix

set_mtime_hours_ago() {

  st="$(date -d "@$s" +%Y%m%d%H%M.%S 2>/dev/null || date -r "$s" +%Y%m%d%H%M.%S)"

}

  date -d "@$s" +%Y%m%d-%H%M%S 2>/dev/null || date -r "$s" +%Y%m%d-%H%M%S

  [ "$a$b" = yesyes ] && [ ! -e "$HOME/~" ] && pass F8 "~/Docs and ~ resolve to \$HOME" \
    || fail F8 "source ~/Docs copied: $a, source ~ copied: $b (want yes, yes; /bin/bash $(/bin/bash -c 'echo $BASH_VERSION'))"
}
check_F9() {  # quoted patterns in the extra column must work or be rejected
  newenv F9; mkfiles "$ICLOUD/D" 2 d; printf 'tmp\n' > "$ICLOUD/D/scratch.tmp"
  jobs "q|copy|iCloudDocs/D|Nx:q|--exclude '*.tmp'"
  if ! validates; then pass F9 "quoted extra flags rejected by validation"; return; fi
  cs run q >/dev/null 2>&1
  [ -e "$T/remotes/nx/q/scratch.tmp" ] && fail F9 "--exclude '*.tmp' accepted but excluded nothing" \
    || pass F9 "--exclude '*.tmp' honoured"
}
check_F10() { # verify --deep must not claim hashes when none were compared
  newenv F10; mkfiles "$ICLOUD/S" 3 s; mkdir -p "$T/remotes/vault"
  printf '\n[Vault]\ntype = crypt\nremote = %s\npassword = %s\n' "$T/remotes/vault" \
    "$("$REAL_RCLONE" obscure test-only)" >> "$RCLONE_CONFIG"
  jobs "v|sync|iCloudDocs/S|Vault:s|"
  cs run v >/dev/null 2>&1
  printf 'data s X\n' > "$ICLOUD/S/s1.txt"          # same size, different bytes
  local out rc; out="$(cs verify v --deep 2>&1)"; rc=$?
  if [ "$rc" = 0 ] && printf '%s' "$out" | grep -q 'matching hashes'; then
    fail F10 "verify --deep says 'matching hashes' although rclone found no common hash"
  else pass F10 "verify --deep does not claim a hash check it did not do"; fi
}
check_F11() { # @prefetch must not materialize the whole Mobile Documents tree
  newenv F11; mkfiles "$ICLOUD/D" 2 d
  cp "$(dirname "$CLOUDSYNC")/examples/icloud.filter" "$HOME/.config/cloudsync/icloud.filter"
  jobs "all|sync|iCloudAll|Nx:backup/iCloud|@prefetch --filter-from ~/.config/cloudsync/icloud.filter"
  cs dry all >/dev/null 2>&1
  grep -qx "brctl download $HOME/Library/Mobile Documents" "$CALLS" \
    && fail F11 "@prefetch ran brctl download on the whole Mobile Documents tree" \
    || pass F11 "@prefetch is scoped (no brctl on the whole tree)"
}
check_F12() { # auto-clean must not remove the lock of a job that is still running
  newenv F12; mkfiles "$ICLOUD/A" 2 a
  jobs "big|copy|iCloudDocs/A|Nx:a|" "other|copy|iCloudDocs/A|Nx:b|"
  sleep 300 & local live=$!; BG_PIDS="$BG_PIDS $live"
  local L="$HOME/.local/state/cloudsync/locks/big.lock"
  mkdir -p "$L"; echo "$live" > "$L/pid"; set_mtime_hours_ago "$L" 13
  cs dry other >/dev/null 2>&1
  local alive; alive=$(kill -0 "$live" 2>/dev/null && echo 1 || echo 0); kill "$live" 2>/dev/null
  [ -d "$L" ] && pass F12 "lock of a live 13h-old run survives auto-clean" \
    || fail F12 "auto-clean removed the lock of a live run (owner alive=$alive)"
}
check_F13() { # owner: no backups on local disks, so a sync into a local path must be rejected
  newenv F13; mkfiles "$ICLOUD/D" 2 d; mkfiles "$T/Volumes/SSD/backup" 3 old
  jobs "ssd|sync|iCloudDocs/D|$T/Volumes/SSD/backup|"
  if validates; then
    cs run ssd >/dev/null 2>&1
    fail F13 "sync into a local path accepted; its deletions went to ~/.cloudsync-backups ($(count "$HOME/.cloudsync-backups") file(s))"
  else pass F13 "sync into a local path rejected (backups never use local disk)"; fi
}
check_F14a() { # indented comment lines must be ignored everywhere
  newenv F14a; mkfiles "$ICLOUD/D" 2 d
  jobs "docs|copy|iCloudDocs/D|Nx:docs|" "  # note to self"
  cs dry all >/dev/null 2>&1 && pass F14a "indented # comment ignored by run all" \
    || fail F14a "indented # comment passes validation but breaks 'dry all'"
}
check_F14b() { # a job name with a space must run via 'all' or be rejected
  newenv F14b; mkfiles "$ICLOUD/D" 2 d
  jobs "my docs|copy|iCloudDocs/D|Nx:docs|"
  if ! validates; then pass F14b "job names with spaces rejected"; return; fi
  cs run all >/dev/null 2>&1
  [ -f "$T/remotes/nx/docs/d1.txt" ] && pass F14b "job name with a space runs via 'all'" \
    || fail F14b "job 'my docs' validates but never runs via 'all'"
}
check_F14c() { # 'schedule install daily 3' must mean 03:00 or be rejected
  newenv F14c
  cs schedule install daily 3 >/dev/null 2>&1; local rc=$?
  local p="$HOME/Library/LaunchAgents/com.user.cloudsync.plist" m
  m="$(grep -o '<key>Minute</key><integer>[0-9]*' "$p" 2>/dev/null | grep -o '[0-9]*$')"
  { [ "$rc" != 0 ] || [ "$m" = 0 ]; } && pass F14c "'daily 3' rejected or scheduled at 03:00" \
    || fail F14c "'daily 3' scheduled at minute $m (want rejected or 03:00)"
}
check_F14d() { # EDITOR with arguments must work
  newenv F14d; jobs "d|copy|iCloudDocs/D|Nx:d|"
  EDITOR="true --wait" cs edit >/dev/null 2>&1 && pass F14d "EDITOR='true --wait' works" \
    || fail F14d "EDITOR with arguments fails ('command not found')"
}
check_F14e() { # doctor must not blame Full Disk Access for a folder named 'Error...'
  newenv F14e; mkdir -p "$ICLOUD/Error Reports"; jobs "d|copy|iCloudDocs/D|Nx:d|"
  cs doctor 2>&1 | grep -q 'NOT readable' && fail F14e "doctor reports no Full Disk Access because a folder is named 'Error Reports'" \
    || pass F14e "doctor reads iCloud correctly with an 'Error Reports' folder"
}
check_F23() { # copy must keep the originals of files it overwrites, like sync (G3)
  newenv F23; mkfiles "$ICLOUD/D" 5 d
  jobs "c|copy|iCloudDocs/D|Nx:c|"
  cs run c >/dev/null 2>&1
  local f; for f in "$ICLOUD/D"/*.txt; do printf 'changed %s\n' "$RANDOM" > "$f"; done
  cs run c >/dev/null 2>&1
  local kept; kept=$(grep -rl '^data' "$T/remotes/nx" 2>/dev/null | grep -c cloudsync-backups)
  [ "$kept" = 5 ] && pass F23 "copy kept all 5 overwritten originals under .cloudsync-backups" \
    || fail F23 "copy overwrote 5 files and kept $kept original(s)"
}
check_F24() { # owner: backups stay 30 days by default; age comes from the folder name
  newenv F24; mkfiles "$ICLOUD/D" 2 d
  jobs "d|sync|iCloudDocs/D|Nx:D|"
  local B="$T/remotes/nx/.cloudsync-backups/d" old new o=kept n=kept
  old="$(ts_days_ago 31)"; new="$(ts_days_ago 29)"
  mkfiles "$B/$old" 1 o; mkfiles "$B/$new" 1 n
  cs clean backups >/dev/null 2>&1
  [ -e "$B/$old" ] || o=purged; [ -e "$B/$new" ] || n=purged
  [ "$o$n" = purgedkept ] && pass F24 "clean backups: 31-day-old backup purged, 29-day-old kept" \
    || fail F24 "clean backups without --days: 31-day-old $o, 29-day-old $n (want purged, kept)"
}

ALL="G1 G2 G3 F1 F2 F3 F4 F5 F6 F7 F8 F9 F10 F11 F12 F13 F14a F14b F14c F14d F14e F23 F24"

for c in ${*:-$ALL}; do "check_$c"; done

[ "$FAILS" = 0 ]
